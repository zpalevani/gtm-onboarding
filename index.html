Part I · The platform

What Tag Manager does, and how it differs from the Google tag

A tag is a piece of code that sends data to a system such as Google Analytics or Google Ads. Tag Manager is a tag management system: you install its snippets on the site once, then add and change tags in the Tag Manager interface instead of editing the site's code.

OptionWhat it isWhen it fits
Google tag (gtag.js)One tag, installed with one snippet per page, that sends data only to Google products (Google Analytics, Google Ads and other "destinations").A simple site that only needs Google measurement and has a developer to edit the code.
Tag Manager web containerTwo snippets per page. Tags, triggers and variables are managed in the interface, with versions, preview and user permissions. Runs Google, third-party and custom tags.Most clients: several tools, a marketing team that changes tags often, or a need for testing and approvals before anything goes live.
Server container (server-side tagging)A second container running on the client's own cloud server. The web container sends one request per event to it, and the server forwards data to each vendor.Clients who need to control what data leaves their site, reduce browser requests, or set first-party cookies from their own server.
Google tag gateway for advertisersServes the Google tag and its measurement requests from the client's own domain, through their CDN, load balancer or server container.Clients who want Google measurement to run first-party with little engineering, especially on Cloudflare, Akamai, Fastly, CloudFront or Google Cloud.
The Google tag and Tag Manager are merging

Google has upgraded every Google tag with Tag Manager features. In November 2026 it announced that each Google tag becomes a full Tag Manager container, with one tag per Google destination. Installations that aren't yet supported get the upgrade in January 2027. Expect clients to ask what this changes for them.

Account, container, workspace, version, environment

Every Tag Manager question starts with "which container, and which version is live?" Changes are drafts until someone with the right permission publishes them.

LevelWhat it representsWhat's set here
AccountUsually one per organization. Should be owned by the client, not by an agency.Account permissions: Admin (creates containers, manages users) or User. Google recommends at least two admins from the client's own team.
ContainerThe set of tags, triggers and variables installed on one website, app or server. Best practice is one per web domain, or one for a single experience that spans domains.Container permissions: No access, Read, Edit, Approve (can create versions) and Publish. Also container settings and, after optimization, shared Google destination settings.
WorkspaceA draft area where someone edits the container. Several people can work in separate workspaces at once.The changes waiting to be published. Each change can be reviewed or abandoned before publishing.
VersionA saved snapshot of the whole container. Every publish creates one.Name and description, who published it and when. Any older version can be published again to roll back.
EnvironmentLive always serves the published version. Custom environments serve a chosen version on staging or test servers.Which version each environment serves. Custom environments have their own snippet; resetting the link breaks the old snippet.
Don't lose the last admin

If an account or container ends up with no admin, Google deletes it automatically. Users with Read access then have 30 days to export it from the trash. Tag Diagnostics warns when an account has only one admin.

The container ID tells you what it can run

Since July 2026 the container ID decides its capabilities: a GTM- container can run any tag, while a Google tag ID (G-, AW-) is limited to tags Google provides.

Part I · The platform

How the data works: triggers, the data layer, consent, destinations and publishing

Clients ask about these six topics more than any others. Open one to read it.

Tags, triggers, variables and firing order
The three parts

A tag sends data. A trigger listens for an event (a page load, click, form submit, custom event) and fires the tags attached to it. A variable is a placeholder for a value, such as the page URL or an order total, used in triggers and tags.

Page-load order
  • Consent Initialization: first, for the consent banner and consent defaults.
  • Initialization: before everything else, for tags such as the Google tag.
  • Page View, then DOM Ready (page structure ready), then Window Loaded (images and scripts finished).
Other triggers

Click, Element Visibility, Form Submission, Scroll Depth, YouTube Video, Custom Event, History Change, JavaScript Error, Timer and Trigger Group. Use "Some events" with conditions rather than firing on everything.

Source: Components of Tag Manager · Page view triggers · Triggers · Built-in variables

The data layer
What it is

A JavaScript list on the page (window.dataLayer) where the site's developer puts events and values, such as a purchase and its total. Tag Manager reads it in order, one message at a time.

Rules that prevent bugs
  • Create it before the container snippet, with window.dataLayer = window.dataLayer || [];, and never replace it after Tag Manager loads.
  • Values only last for the current page. Push them again on every page that needs them.
  • Pushes are queued. If the next tag needs a value, push it with an event name and fire the tag on a Custom Event trigger.
  • The name is case-sensitive: dataLayer, not datalayer.
Why it matters

Business values such as order totals are far more reliable from the data layer than read from the page's text or layout, which breaks when the site is redesigned.

Source: The data layer · Components of Tag Manager

Consent mode
What it does

Tells Google tags whether the visitor agreed to cookies and ads use of their data. Four main consent types: ad_storage, analytics_storage, ad_user_data and ad_personalization (the last two were added in consent mode v2, November 2023).

Basic vs advanced
  • Basic: Google tags don't load until the visitor accepts. Nothing is sent before that.
  • Advanced: tags load with "denied" defaults and send cookieless pings, which let Google model the conversions it can't observe.
Order matters

Set the consent default before any Google tag runs (on the Consent Initialization trigger), then send an update when the visitor chooses. Defaults can differ by region. In Tag Manager, use a consent template or an integrated consent banner, not a Custom HTML tag.

Source: Consent mode overview · Set up consent mode · Tag Manager consent mode support

The Google tag, destinations and container optimization
Destinations

Google Analytics, Google Ads and Floodlight are "destinations" of the Google tag. Settings such as cross-domain linking, internal traffic, session timeout and consent overrides are set once in the Google tag settings and apply to every destination on it.

Optimizing a container

Since October 2026 Google recommends optimizing Tag Manager containers: the container sends data straight to Google destinations without loading gtag.js, shared settings move to a new Settings tab, and each destination gets its own tag. It isn't automatic: someone with Edit access or higher starts it from a banner, the changes land in a workspace, and you preview before publishing.

Watch out

Existing event tags and triggers are kept, but shared settings now apply across destinations, so preview carefully. Access granted during optimization isn't part of the container version.

Source: Configure your Google tag settings · Optimize your Tag Manager container · Updates to the Google tag and Tag Manager (August 2026)

Preview, versions and publishing
Preview

Click Preview in the workspace to open Tag Assistant, enter the site URL and connect. You browse the site as if the draft were live, and see which tags fired, in what order, with the data layer and variable values for each event. Only you (or people you share the preview with) see it.

Publishing

Submit → Publish and Create Version, with a clear version name and description. Publishing needs Publish permission. Approval workflows are a Tag Manager 360 feature.

Rolling back

From Versions, publish an earlier version. "Set as Latest Version" only resets the draft; it doesn't change the live site until you publish.

Source: Preview and debug containers · Publishing, versions and approvals

Server-side tagging and the Google tag gateway
Server-side tagging

A server container runs on the client's own cloud project (Google recommends Cloud Run). Clients inside it receive requests and turn them into events; tags then send data to each vendor. Data can be checked, cleaned or removed before it leaves, and cookies can be set from the client's own subdomain or path.

Google tag gateway

Serves the Google tag from a path on the client's domain (for example /metrics) through their CDN, load balancer or server container, which forwards measurement to Google. It's set up from the Google tag or Tag Manager admin screen and checked in Tag Assistant.

They work together

If the client already runs server-side tagging, Google says to turn on the gateway in the server container. Otherwise the CDN or load balancer route is usually simpler.

Source: Introduction to server-side tagging · Google tag gateway implementation flow · Set up the gateway with your CDN

Part II · Learn the language

Five things that will confuse you, and what to do

"My tag didn't fire"
Why it happens

The trigger's conditions didn't match; an exception trigger blocked it; a consent check required consent the visitor hadn't given; the tag is paused; or the change is still in a workspace and was never published.

What to do

Open Preview, select the event where the tag should have fired, and look at Tags Not Fired: the tag's details show which trigger condition failed. Then check its consent settings. See Preview and debug containers and consent mode support.

A variable shows "undefined" or the previous page's value
Why it happens

The value was pushed to the data layer after the tag fired, pushes are queued behind other messages, the data layer was replaced after Tag Manager loaded, or the key name doesn't match exactly (names are case-sensitive).

What to do

In Preview, open the event's Data Layer tab to see what was really there. Ask the developer to push the value with an event name, and fire the tag on that Custom Event trigger. See The data layer.

Conversions dropped after a consent banner went live
Why it happens

Some drop is expected when visitors decline. A big drop often means Google tags are fully blocked (by exception triggers, extra consent checks, or the banner's own auto-blocking), so they can't send the cookieless pings used for conversion modeling. Or the consent default runs after the tags.

What to do

Check in Tag Assistant whether Google tags are firing with denied consent. If the client chose advanced consent mode, remove consent-based exception triggers from Google tags and set their additional consent checks to "Not set". See Unblock Google tags with consent mode.

Page views doubled after a migration or optimization
Why it happens

A hard-coded Google tag still runs on the page alongside Tag Manager, or a container migrated from gtag.js had its "Support gtag('config') initialization events" setting changed without moving the page's settings into the tags first.

What to do

In Preview, confirm there's exactly one page_view per page and look for duplicate Google tag snippets in the page source. See Manage legacy gtag('config') behavior.

"It works in Preview but not on the live site"
Why it happens

Preview shows the workspace draft. The change was never published, was published to a custom environment instead of Live, or the live site loads a different container ID.

What to do

Check the Versions list for what's published, and to which environment. Confirm the container ID in the page source matches. See Publishing and versions and Environments.

Escalate nowA container is flagged for malware
Why it happens

Tag Manager scans containers automatically. Tags that point to a site where malware was found won't fire, and the container shows a malware alert. Re-enabling a disabled tag can lock users out of the account.

What to do

Tell your Tag Manager lead right away. Don't try to re-enable the tag. The fix is to remove its triggers and republish, which an admin should do. See Malware detection.

Design the purchase data layer and trigger.

Deliverable to record

What the developer should push to the data layer when an order completes, the trigger that fires the purchase tags, and the variables those tags read.

What you'll understand afterwards

How the site, the data layer, triggers and variables connect, and why business values shouldn't be read from the page's text.

Hint
  • GA4 has a recommended purchase event. Which values does it need?
  • Which trigger type listens for an event name pushed to the data layer?

What a good answer looks like
  • Push: on the order confirmation, dataLayer.push({ event: 'purchase', ecommerce: { transaction_id, value, currency, items: [...] } }), following the GA4 ecommerce format, with the data layer created before the container snippet.

  • Tags: the GA4 purchase event and the Google Ads conversion on that trigger, plus the third-party pixel if it's allowed under consent.
  • Duplicates: the transaction ID lets GA4 recognize a repeated purchase; the developer should also push it only once per order.

Part III · Module 1 of 4

When does a client need server-side tagging or the tag gateway?

Your job is to recognize the needs these options are built for, ask the right questions, then bring in a consultant to confirm.

Signals that point to server-side tagging
  • Control over what data leaves the site, such as removing personal information before it reaches vendors. Source
  • Many tags slowing pages down: one request per event goes to the server instead of one per vendor. Source
  • Cookies set from the client's own server, through a subdomain or a path on the same site. Source
  • Data from apps or other servers sent in the Measurement Protocol format. Source
Signals that point to the tag gateway
  • Mostly Google tags, and a wish for first-party measurement with little engineering. Source
  • Already on a supported CDN or load balancer: Cloudflare, Akamai, Fastly, CloudFront or Google Cloud. Source
  • Judgment Neither option is a way around consent or ad blockers, and neither is worth it if nobody will maintain it. These are our views, not Google's wording.
Scenario

A retailer with three brands runs its sites on Akamai. Each brand has its own Tag Manager container, and all three use consent mode. It asks you to "just switch on the Google tag gateway" for better measurement.

What would you recommend?
Show the reasoning and the questions to ask

Why not the automated setup straight away: Google's Akamai guide says the integration supports only one Google tag configuration, and that several may make the gateway work incorrectly and be open to script injection. It also says sites using consent mode must turn off automated script setup. Three containers on consent mode hit both limits.

What to find out before recommending:

  1. Are the three brands on separate Akamai properties and domains, or one?
  2. Could the brands share one container and one measurement path, or should they use the self-service setup?
  3. Which measurement path would they use? Akamai's costs are only waived with its native template and a short path.
  4. Does Akamai pass the visitor's country and region to Google? Manual setups must add these headers.
  5. Who will own the Akamai configuration after launch?

Bring in a technical consultant to confirm the setup before the recommendation goes to the client.

Sources: Set up the gateway with Akamai · Gateway implementation flow · How the gateway sets location

Part III · Module 2 of 4

Recognizing common client issues

You don't need to fix these. Ask good questions, check what you can, and know when to hand over. The causes listed are possibilities to investigate, not diagnoses.

1. "Our conversions dropped after we launched a cookie banner"
What the client sees

Fewer conversions in Google Ads or GA4 from the day the banner went live.

Ask first
  • Which banner, and was it set up through Tag Manager?
  • Basic or advanced consent mode?
  • Which countries saw the drop?
Possible causes

Expected drop from visitors declining; Google tags fully blocked so no cookieless pings; consent default running after the tags; the banner's auto-blocking catching Google tags.

You can check

In Preview or Tag Assistant: whether Google tags fire with denied consent, and when the default is set.

Escalate when

Consent settings or triggers need changing. That affects legal compliance.

Source: Unblock Google tags with consent mode · Set up consent mode

2. "Our numbers changed after the container was optimized"
What the client sees

Page views, sessions or conversions shift after the optimization banner was accepted or the Google tag was unified with Tag Manager.

Ask first
  • Which version introduced it, and when was it published?
  • Did the Google tags have different settings before they were combined?
  • Is there still a gtag('config') command on the page?
Possible causes

Shared settings (domains, cookie settings, internal traffic) now apply to every destination; the legacy gtag('config') setting changed; config commands firing wildcard Custom Event triggers.

You can check

Compare the two versions in Versions, and the Settings tab's Google destinations.

Escalate when

A rollback or settings change is needed.

Source: Optimize your container · Legacy gtag('config') behavior · Release notes

3. "Our developer says Tag Manager is slowing the site"
What the client sees

Slow pages, or a performance tool pointing at the container.

Ask first
  • How many tags, and how many are Custom HTML?
  • Is one container shared across several sites?
Possible causes

A large container (the Versions page shows a size indicator; Google suggests optimizing above 70%); many Custom HTML tags or Custom JavaScript variables; unused tags; very long lookup tables.

You can check

The container size indicator and how many tags are paused or unused.

Escalate when

Tags need consolidating or moving to server-side tagging.

Source: Manage container size and efficiency

4. "Someone published a change we didn't approve"
What the client sees

A tag changed or appeared on the live site without sign-off.

Ask first
  • Which version, and who published it?
  • How many people have Publish permission?
Possible causes

Too many users with Publish; no approval process (approvals need Tag Manager 360); an agency publishing directly.

You can check

Versions shows who published what. User Management shows who holds Publish.

Escalate when

Permissions need changing (only an admin can), or the change must be rolled back.

Source: User permissions · Publishing, versions and approvals

5. The tag gateway shows "Pending", or reports show the wrong countries
What the client sees

A domain stuck on Pending, Paused or Not started, or GA4 locations clustered on the CDN's location after the gateway went live.

Ask first
  • Automated or manual setup, and on which CDN?
  • When was it turned on?
Possible causes

Pending means it's enabled but no diagnostics have arrived yet. Wrong locations usually mean a manual setup isn't sending the visitor's country and region headers, or is altering the visitor's IP address.

You can check

The gateway status per domain, and hits to the measurement path in Tag Assistant.

Escalate when

CDN rules or headers need changing. Wrong regions can also make regional consent defaults misfire.

Source: Gateway with Cloudflare in Tag Manager · How the gateway sets location

Part III · Module 3 of 4

Tag Manager enterprise architecture

Three building blocks come up in almost every enterprise conversation.

Tag Manager

Accounts, containers and permissions

One account per organization, one container per site, with workspaces, versions and environments.

Why organizations use it
  • Agencies and teams can edit without being able to publish.
  • Every change is versioned and can be rolled back.
  • Staging sites can run a different version from Live.
Limitations
  • Configuration can't be shared between containers except by export and import or the API.
  • Approval workflows and Zones need Tag Manager 360.
  • Publishing a container publishes it on every domain it's installed on.
Scenario

A group with five country sites gives each site its own container, lets local teams Edit, and keeps Publish with a central analytics team.

Google tag + consent

Destinations and consent mode

The Google tag sends to GA4, Google Ads and Floodlight, governed by consent mode.

Why organizations use it
  • One place for cross-domain, internal traffic and cookie settings.
  • Consent defaults by region, with modeling for unobserved conversions.
  • Consent Overview to review every tag's consent settings at once.
Limitations
  • Shared settings apply to every destination on the tag.
  • Tag Manager's consent settings support only TCF Purpose 1 for the IAB framework.
  • Consent mode doesn't store the choice; the banner must.
Scenario

A publisher uses an integrated consent platform with denied defaults in the EEA and a consent mode override in the Google tag as a safety net.

Source: Google tag settings · Consent mode support · Consent mode override

Server-side + gateway

First-party data collection

A server container on the client's cloud, and the gateway serving Google tags from the client's domain.

Why organizations use it
  • Clean or remove data before vendors receive it, with transformations.
  • Fewer browser requests and server-set cookies.
  • Google tags served from the client's own domain.
Limitations
  • Server-side tagging needs cloud servers, a custom domain and ongoing maintenance.
  • The Cloudflare gateway applies to the whole zone, and Akamai and Fastly support one Google tag configuration.
  • Only Google first-party cookies pass through the gateway; others are dropped.
Scenario

A retailer runs server-side tagging on Cloud Run behind a load balancer, turns on the gateway in the server container, and strips email addresses from events before they reach a third-party tool.

Source: Transformations · Custom domains · Cloudflare gateway · Gateway cookie handling

Understanding costs, Tag Manager 360 and support

Tag Manager itself is free, so clients are often surprised by a bill. Three things explain most of it.

Platform

1. Tag Manager and Tag Manager 360

Standard Tag Manager has no fee. Tag Manager 360 is part of Google Marketing Platform and adds approval workflows, Zones for large containers, and enterprise support.

Source: About Tag Manager 360 · Approvals · Tag Manager 360 support

Cloud

2. Server-side hosting

The automatically created setup is for testing only. For live traffic, Google estimates about $45–50 per server per month on Cloud Run, with at least two servers (Google's pages say two or three), plus network and logging costs. Request logs can be excluded at high volume to save money.

Source: Cloud Run setup guide · Server-side overview

Gateway

3. Tag gateway costs

Cloudflare says its gateway is free and doesn't count toward other Cloudflare billing. On Google Cloud, the integration is free but the load balancer's usage is billed (Google says Google Ads covers the extra processing). On Akamai, serving costs are waived only with the native template and a short measurement path.

Source: Cloudflare gateway · Gateway with Google Cloud Load Balancer · Gateway with Akamai

Scenario

A client asks: "Tag Manager is free, so why are we getting a Google Cloud bill?"

Show a good answer

"Tag Manager itself is free. The bill comes from the server-side tagging setup, which runs on servers in your own Google Cloud project. You pay for those servers, the data they send and their logs, like any cloud service. Google estimates about $45 to $50 per server per month, and recommends at least two servers for live traffic."

Then offer to review the project's server count, autoscaling limits and logging settings with your technical team. Never quote a client's exact cost without looking at their billing report.
